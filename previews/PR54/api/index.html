Every exported name that carries a docstring appears below. The guide pages give worked examples: Tutorial, Experiments, Recompilation, Compile options, Optimization, and Schedules.

ReactantNitro.ReactantNitro — Module
ReactantNitro

A training framework for Lux models compiled with Reactant.

The central object is a Nitro. Nitro(e) runs setup only, so validate, evaluate and predict work without training; train! trains it. A run is one train! of a Nitro, which is what the run_* accessors are named for.

source
ReactantNitro.ASAM — Type
ASAM(rho; eta = 0.01f0, m = nothing)

Adaptive SAM (Kwon et al. 2021), which perturbs each parameter in proportion to its own size.

The gradient is taken at ps + ε with ε = rho * T² g / ‖T g‖ and T = |w| + eta, so the sharpness it measures is invariant to rescaling the weights. Leaves adaptive_perturb declines (by default the rank-1 leaves: biases, norm affines, scalar parameters) get T = 1, as under SAM. rho is relative, so typical values are about ten times SAM's, around 0.5 to 2 with SGD and smaller with Adam-family rules. eta is not schedulable; m is reserved, as for SAM.

ReactantNitro.Average — Type
Average(sel::Selector; weight = :uniform, state = nothing)

The parameters of the checkpoints sel picks from one run, averaged, as a weights source:

Nitro(e; weights = :latest => Average(Last(10)))Nitro(e; weights = "a1b2c3" => Average(Best(5; among = Last(20))))

weight is :uniform, the only weighting so far. Lux state is not averaged: it comes from one picked checkpoint, the best when sel ranks (a Best) and the latest otherwise, or as state = :best | :latest says. That is exact for a model without running statistics and an approximation for one with them, such as BatchNorm. The optimizer starts fresh, so restore_optimizer = true and resume refuse an Average. Averaging across runs (:all) is refused for now. The run must still hold every checkpoint sel names; keep them while training with Checkpointer(; keep), for example keep = (Best(3), Last(10)).

ReactantNitro.Best — Type
Best(k = 1; among = nothing)

The k best entries by the checkpointer's metric and mode. Only entries scored under that pair are ranked; under scope = :dir, every run's entries compete. among, a selector, ranks only what it picks: Best(5; among = Last(20)) is the best 5 of the latest 20. among is for loading, as in Average; keep refuses it.

ReactantNitro.Checkpointer — Type
Checkpointer(; keep = (Best(3), Last(1)), metric = nothing, mode = nothing, dir = nothing,
               name = nothing, scope = :run)

The default checkpointer. After each epoch it writes a full CheckpointRecord into run_dir if some selector in keep would retain it, then keeps the union of what the selectors pick and deletes the rest. The default, (Best(3), Last(1)), keeps the best 3 by metric (lower is better under mode = :min, higher under :max) plus the latest, whatever it scored. checkpointer = nothing disables checkpointing.

Checkpointer(; keep = (Best(3), Last(10)))   # the best 3 and the latest 10, for averagingCheckpointer(; keep = Last(5))               # a rolling windowCheckpointer(; keep = Best(3))               # the best 3 only

metric and mode default to nothing, which follows the run's monitor; give both to rank by something else. Setup fills a following checkpointer in, every time it builds a Nitro. A checkpointer used without setup (in average_checkpoints, say) ranks by the metric and mode the run's newest scored entry was written under. dir and name left as nothing are filled in at setup: dir with run_dir, and name, the filename function name(; epoch, step, metric, score), with the experiment's checkpoint_filename.

A manifest, manifest.jld2, lists each retained file with its epoch, score, stop_reason, and the run, metric and mode that wrote it, so lookups and resume never open a record; see read_manifest. The latest checkpoint is found through it rather than a latest symlink, which would dangle once rotation deleted its target.

Without a Last, an epoch no selector admits is not written at all, rather than written and deleted. The final stop_reason rewrite follows the same rule, so the state training ended in is saved only if a selector keeps the last epoch, and weights = :latest => :latest and resume = :auto resolve to the latest kept epoch, not to where training stopped. A crash loses every epoch since then. Setup warns about this for a handle that trains, and refuses keep with only Best selectors for a training run with no val split, whose epochs have no score.

scope = :run, the default, applies retention to this run's checkpoints only. A directory often holds several runs (the default run_dir is the experiment's type name), so setup gives each run an id, the field run, and never ranks, rotates, deletes or overwrites another run's checkpoints. A fresh run gets a new id. A resume from a run's latest record continues that run's id; a resume from any other record starts a new id and records its source path in parent. Setup sets both fields for every Nitro it builds, so a checkpointer reused across handles belongs to the most recent one. A checkpointer used without setup has run = nothing, the same unnamed run as manifest entries written before runs were recorded.

scope = :dir saves space: Best ranks the whole directory, across every run, and a write deletes every other entry scored the same way, including other runs'; Last and the other selectors keep this run's own entries. Setup warns a training handle when the directory already holds checkpoints this may delete.

Only entries scored under the current metric and mode are ranked. Entries written under another pair, by an earlier run or before a resume changed the selection, are never ranked or deleted, under either scope. Setup and :best lookups warn when the entries they consider are mixed this way. An entry with no recorded metric predates the field and counts as matching. Under either scope, a filename that would overwrite a file this run does not own gets -run-<id> inserted before .jld2.

ckpt.k (the largest Best's k, else 0) and ckpt.keep_latest (whether keep has a Last) remain readable for code written against TopKCheckpointer, and are deprecated.

ReactantNitro.Decay — Type
Decay(lambda)
Decay(lambda, anchor)
Decay(lambda, anchor, no_decay_mask)

Decoupled weight decay toward an anchor: apply! adds no_decay_mask * lambda * (x - anchor) to the update, or no_decay_mask * lambda * x when anchor === nothing. The anchor comes from the group's decay_anchor:

decay_anchoranchorDecays toward
:zero (default)nothingzero (ordinary weight decay)
:w0that group's w0 slicethe pretrained weights (L2-SP)
an arraythat arrayan explicit target

A group whose lambda is zero gets no Decay in its chain. anchor === nothing is resolved by type, so plain decay emits no subtraction. Decay must be the last rule in a chain, after the base rule as in AdamW, so lambda arrives pre-multiplied by the group's learning rate; any other position is a setup error. The anchor is a field rather than state captured at init, which on a resume would capture the restored weights. There is no WeightDecay alias, since Optimisers.WeightDecay already uses that name.

ReactantNitro.Device — Type
Device{T}

Declaration-time marker for an @experiment field; the macro consumes it and records the field in device_fields. A Device field is converted to device residency at setup and reaches the traced step as an input, so e.aux_weight in a hook is the device value. The marker places the value on the device, keeps it out of the compile cache key (a traced input cannot change the graph), and makes it schedulable (a constant and a schedule use the same slot). Mark what you intend to change or schedule without recompiling; a Device threshold of zero still emits ops that a host 0f0 would fold away.

@experiment struct MyExp    "Weight of the auxiliary heatmap loss relative to the primary term."    aux_weight::Device{Float32} = 0.25f0end

See also Host, the default, and GraphConst, which bakes.

ReactantNitro.EMA — Type
EMA(beta; warmup = true, every = 1)

An exponential moving average of the weights, θ_ema ← β θ_ema + (1 - β) θ, updated after every every-th optimizer step. warmup uses min(beta, (1 + t) / (10 + t)) at optimizer step t, so the average is not dragged by the initial weights for 1 / (1 - beta) steps. Set it with the ema accessor or the Nitro keyword:

ReactantNitro.ema(::MyExp) = EMA(0.999)

The average starts as a copy of the weights training starts from, is checkpointed in the record's ema field and restored by a resume. Under eval_weights = :ema (the default with an EMA), validation, checkpoint selection, predict, restore_best and export use it; training and parameters use the raw weights. Nitro(e; weights = ..., load_ema = true) loads a record's average in place of its weights. The average has the weights' element type.

ReactantNitro.EarlyStopping — Type
EarlyStopping(; metric = nothing, mode = nothing, patience = 5, min_delta = 1f-4)

Stop training when a validation metric stops improving. Pass it as the early_stop keyword or accessor; the default nothing never stops early.

metric and mode default to nothing, which follows the run's monitor; give both to watch something else. patience counts epochs without improvement, and an epoch improves when it beats the best so far by more than min_delta (absolute, as in Keras and Lightning). Setup requires a val split and checks mode, patience and, for an experiment without metrics, that metric is :loss. With a custom metrics the key cannot be checked before it runs, so a misspelled one raises after the first epoch's validation.

train!(e; early_stop = EarlyStopping(; patience = 5))                              # the monitortrain!(e; early_stop = EarlyStopping(; metric = :loss, mode = :min, patience = 5))

The stopping epoch still validates and checkpoints, then train! returns through Done with stop_reason = :early_stop, which the final checkpoint record stores. request_stop! stops at the same point on demand, with stop_reason = :requested. Setup copies the instance with the monitor filled in and fresh best and wait counters, so two handles never share them and the instance you passed is not mutated; the handle's copy is nitro.early_stop. The counters are stored in each checkpoint, and a resume that watches the same metric and mode continues from them.

ReactantNitro.GraphConst — Type
GraphConst{T}

Declaration-time marker for an @experiment field. A GraphConst field bakes as a trace-time constant and enters the compile cache key: the tracer sees a real Int with ordinary control flow, and a changed value recompiles. Use it for structure: layer counts, widths, variant selectors. ReactantNitro.Host — Type
Host{T}

Declaration-time marker for an @experiment field, and the default for an unmarked one: max_epochs::Int = 40 means max_epochs::Host{Int} = 40. A Host field is never converted, never hashed into the compile cache key, and never visible to the tracer. This keeps driver knobs out of the key, and keeps dataset-sized state away from Reactant and Enzyme, which walk the whole Const(e) argument element by element at every compile. compile_view replaces every Host field with a StrippedHost sentinel at every trace site.

See also Device and GraphConst.

JSONLogger(path) -> JSONLogger
JSONLogger() -> JSONLogger

The default logger: writes JSON Lines to path, or, when constructed without one, to metrics.jsonl in the run's run_dir. logger(e) returns a pathless one when the experiment declares no logger, so a plain Nitro(e) writes runs/<Exp>/metrics.jsonl beside its checkpoints. ReactantNitro.Nitro — Type
Nitro(e; kwargs...) -> Nitro

The state of a run: model, weights, optimizer, data and counters. Nitro(e) runs the setup sequence and nothing else, so validate, evaluate and predict work without training in the process. train!(e; kwargs...) is shorthand for train!(Nitro(e; kwargs...)), so every run keyword is a Nitro keyword.

nitro = Nitro(e)                                  # fresh weights from build_modelnitro = Nitro(e; weights = :latest => :best)      # best weights of the newest run in run_dirnitro = Nitro(e; data = (; test = loader))        # supply data directly, skip build_datanitro = Nitro(e; compile_options = (; cudnn_hlo_optimize = true,    # Reactant compile keywords,    xla_debug_options = (; xla_gpu_exhaustive_tiling_search = true))) # XLA flags among them

compile_options applies to every program the handle compiles and is part of each program's compile-cache key; see ReactantNitro.check_compile_options.

Read it through accessors: experiment, parameters, states, run_dir, current_step, current_epoch, phase, history and logger_info; request_stop! is the one write. It holds no Enzyme shadow dps, which exists only inside the gradient program.

ReactantNitro.Nitro — Method
Nitro(e; seed, resume, run_dir, data, n_devs, weights, accum, max_epochs, schedules,
         gradient_clip_norm, check_divergence, autolog_schedules, log_every_n_steps, logger,
         checkpointer, early_stop, monitor, eval_loss, ema, run_ref, w0, restore_optimizer, restore_best,
         eval_weights, load_ema, compile_options) -> Nitro

Build a handle for experiment e by running the setup sequence below. Nothing is trained or compiled.

Sixteen keywords default to the accessor of the same name: seed, run_dir, n_devs, accum, max_epochs, schedules, gradient_clip_norm, check_divergence, autolog_schedules, log_every_n_steps, logger, checkpointer, early_stop, monitor, eval_loss and ema. Passing one replaces the accessor's value for this run; omitting it calls the accessor, before step 1. data, weights, resume and run_ref have no accessor, since each names a fact about this construction: data supplies the collection and skips build_data, and run_ref, a Ref, receives the handle when construction finishes. compile_options passes Reactant compile keywords to every program the handle compiles (see ReactantNitro.check_compile_options).

The fresh sequence

#StepWhy here
1Validate config: accum and log_every_n_steps ranges, driver-only field markers, learning_rate(e) != 0, the clip type, metric residenciesCheapest failures first
2Seed the global rngBefore anything that draws (3 and 6)
3build_data(e, dist)derive needs data
4derive(e, data), merged into eReturns host values, so before conversion; may change the architecture, so before build_model
4.5setup_devicesConversion places values on the mesh
5Convert Device fields to device; e's type changes hereAfter every hook that produces config, before every hook that is traced
6build_model(e, rng)Sees the post-conversion e
7Capture w0Immediately after, before any restore or step
8Param groups, the flat permutation, the per-group rangesNeeds ps; unconditional, since the resume path validates against it
9Training only. Flatten ps, build optimizer state, normalize it to device residencyNeeds the layout
10Resolve routing against typeof(compile_view(e)) from the first batchNeeds the batch schema and the hooks
11Training only. Check length(train) % accum == 0; resolve the horizon and call each schedule factory onceNeeds length(train), accum, max_epochs
12Reattach the logger on resume; log the parameters and the seedBefore the first compile, which can crash

Steps 9 and 11 run after step 10. Each program is traced and compiled, against compile_view(e), by the first verb that runs it.

build_data and derive see the pre-conversion experiment, where Device fields hold host values; every other hook sees the post-conversion one.

Resume adds steps: before 1, locate and load the checkpoint; at 2, take seed from the record, with a warning if it differs, since a seed sweep sharing one run_dir would otherwise become N identical runs without notice; after 4, check config compatibility; after 7, restore ps and st, keeping the fresh w0 capture to verify against the record's anchor_checksum; after 8, refuse a flat permutation or anchor checksum that differs; at 9, restore opt_state and re-normalize it to device residency, without which a resumed run trains at the wrong point of its optimizer's bias correction with no error. step and epoch come from the record.

Checkpoint sources. weights and resume name a checkpoint the same way: a path, or run => checkpoint, resolved to a file through the manifest (resolve_source).

Run (left)Means
:latestthe most recent run in run_dir: the run of the entry written last (legacy entries count as oldest)
"<id>"that run; runs(run_dir) lists the ids, checkpoint_run(n) is a handle's own, "legacy" the unnamed run of an old manifest
:allevery run in run_dir, only as :all => :best
other::Nitrothat handle's own run, in its own run directory
Checkpoint (right)Means
:bestthe run's best record by the current checkpointer's metric and mode (for other, its checkpointer's)
:latestthe run's newest retained record
:currenta live handle's in-memory state; only as weights = other => :current
Average(sel)the run's checkpoints Average picks, averaged; only for weights

Best(1) and Last(1) are the same as :best and :latest; any other Selector may pick several checkpoints, so a source takes it only inside Average.

Bare :best and :latest are refused, naming the pair to use (weights = :latest => :best), as is :all => :latest, which is :latest => :latest. A source that cannot be found raises, naming the directory and the runs it holds. :best selects among entries scored under the current metric and mode only, warns when the run also holds entries under another, and raises when it holds none under the current one, listing the ones it has.

resume is always exact continuation: parameters, layer state, optimizer state, step, epoch and schedule position, under the compatibility checks. It is false (the default), a path, run => :latest | :best with any run above including other, or :auto, which is exactly :latest => :latest and logs what it resolved to, except that a directory with nothing to resume starts a fresh run with a warning (:latest => :latest raises there). One run_dir can hold several runs, each with its own id in the manifest; see Checkpointer. Resuming a run's newest record continues that run: its id is adopted and later checkpoints join it. Resuming anything else (an earlier record such as :best, :all => :best, or a file this directory's manifest does not list) branches into a new run, so the original run's later epochs are never overwritten, and logs that it does. Under a checkpointer with no Last in keep (what keep_latest = false builds) a run's latest record is its most recent kept epoch rather than where it stopped, and the epochs after it are trained again. resume = other and other => :current, a continuation from the handle's in-memory state, are not supported yet; weights = other takes the parameters.

weights names where the initial parameters come from, and takes no training position: no step, no epoch, no schedule position, and no optimizer state unless restore_optimizer asks. A handle built this way that trains is a new run in run_dir, and a directory already holding checkpoints keeps them (under the default retention scope = :run).

  • weights = path or run => :best | :latest restores ps and st from a checkpoint record, and the derived values with them, so derive is skipped and the construction works with no training data. An older record holds no list of derived keys, so for it derive runs and the record's Device values override what it returns. Reloading a finished run's best weights needs no file name:

    n = Nitro(MyExp, :baseline; run_dir = "runs/my_run", weights = :latest => :best, logger = nothing)

  • weights = run => Average(sel) restores the average of the run's checkpoints sel picks, with st and the derived values from one of them (see Average), and records what it averaged in averaged_from. average_checkpoints writes the same record to a file.

  • weights = other::Nitro, or other => :current, is a warm start from a handle in this process: ps and st are taken after step 7, through host memory, and otherwise the fresh sequence runs. The trees must match leaf for leaf.

restore_optimizer = true also restores the optimizer state of a weights record (a path or any run => :best | :latest), normalized to device residency as a resume normalizes it and checked against the optimizer this run builds (rule and group layout; a mismatch is refused), while step, epoch and the schedule start fresh: a new run with a new schedule and max_epochs. It refuses a source that is not a record (none, a bare Nitro, other => :current: restoring a live handle's optimizer is not supported yet), refuses alongside resume, which restores the optimizer anyway, and refuses on a handle with no train split, which has no optimizer to restore into.

restore_best = true ends every train! that does not fail (completion, early stop, a requested stop) by loading this run's own best checkpoint, under the current metric, into ps and st; step, epoch, history and the last metrics stay as training ended. checkpoint_source becomes that file, so export provenance names it, and show says the handle holds it. With no scored checkpoint it warns and keeps the final weights. A handle restored this way refuses a later train!, and the error shows the three constructions that continue from the best checkpoint.

restore_best = Average(sel) ends train! holding the average of the run's own checkpoints that sel picks instead, exactly as weights = run => Average(sel) would load them. Setup refuses a checkpointer whose keep cannot hold that selection; a run that ends before it has enough (an early stop, say) warns and keeps its final weights.

eval_weights is :ema (the default with an EMA) or :raw (the default without one), and says which weights validation, checkpoint selection, predict and export read. load_ema = true loads the weights source's EMA in place of its weights: a record's, an average of records' (run => Average(sel)), or another handle's. A source without one is refused.

w0 says what decay_anchor = :w0 anchors to: :build_model (the default), :weights (the transferred parameters, for L2-SP fine-tuning), or a parameter tree.

checkpoint = path is the deprecated spelling of weights = path. It still works, warns once, and will be removed in a later release.

Without a train split steps 9 and 11 are skipped. Routing falls back to the first batch of whichever split exists; with no split at all it is deferred to the first predict call.

Progress. The sequence is reported as one "setup" stretch of unknown length, with the current step as its phase (setup [building data]), closing as setup done. See progress_reporter!.

Nitro(E::Type, preset::Symbol; kwargs...) -> Nitro

Build the experiment from from_preset(E, preset) and record which named recipe the run claimed, so the name reaches the checkpoint record and log_params!.

n = Nitro(MyExp, :baseline; max_epochs = 40, aug_rotate_deg = 9.0)#                              ^ run keyword    ^ field, so it overrides the recipe

This is shorthand for Nitro(from_preset(MyExp, :baseline; ...); preset = :baseline), which still works but names the preset twice, and nothing checks that the two agree.

ReactantNitro.Plateau — Type
Plateau(inner; metric = nothing, mode = nothing, factor = 0.1, patience = 10, cooldown = 0,
        threshold = 1f-4, threshold_mode = :rel, min_scale = 0)

A schedule factory that multiplies inner by a scale, and reduces the scale when the validation metric stops improving. inner is any schedule factory or a bare Number; a bare number is PyTorch's ReduceLROnPlateau. metric and mode default to nothing, which follows the run's monitor; give both to watch something else. It works on every schedule key: opt (bare and group paths), device, grad and bind.

schedules(e::MyExp) = (;    eta = Plateau(total -> OneCycle(total, 1f-3); patience = 3),)

The value at step t is inner(t) * scale. The scale starts at 1 and is updated once per epoch, after validation, with PyTorch's rule and defaults:

  • an epoch improves when the metric beats the best so far by more than threshold, relative (best * (1 - threshold) for :min) under threshold_mode = :rel, or absolute (best - threshold) under :abs
  • after more than patience epochs in a row without improvement, scale = max(scale * factor, min_scale), and the next cooldown epochs count no bad epochs

So patience = 2 reduces at the third bad epoch, as in PyTorch, and patience = 0 reduces at every bad one. A reduction applies from the next epoch's first step.

Each value is a pure function of the step and the run's validation history. The counters are stored in each checkpoint, so a resume continues the same sequence; a weights load starts fresh. Each key gets its own counters. The train line logs the scaled value as usual, the validation line logs schedule/plateau/<key>, and each reduction is reported with @info.

Setup requires a val split, mode in (:min, :max), 0 < factor < 1, patience >= 0, cooldown >= 0, and, for an experiment without metrics, metric = :loss. With a custom metrics, the key cannot be checked before it runs, so a misspelled one raises after the first epoch's validation.

ReactantNitro.PrefetchIterator — Type
ReactantNitro.PrefetchIterator(source; workers = default_prefetch_workers(),
                               device_batches = 1, host_batches = 2 * workers, ordered = true)

Prefetch settings for a split: workers producer tasks build host batches, one transfer task copies them to the device, and a Channel of device_batches (host, device) pairs feeds the loop.

The framework wraps every split in one of these at the defaults (see auto_prefetch). Construct one only to change the defaults; NoPrefetch opts a split out.

  • workers sets throughput. Buffering only adds lookahead: a producer slower than the device starves it at any device_batches. More than one worker needs batch_at and begin_epoch! on the source; without them the split gets one producer, and setup warns for the training split.
  • device_batches bounds batches staged on the device. Resident device memory is (device_batches + 2) x batch (the channel, the transfer task's hand, the consumer's hand), hence the default of 1.
  • host_batches bounds batches on the host at once, across the workers, the hand-off channel and the reorder buffer. It must be at least workers, or ordered delivery can deadlock waiting on a batch that was never handed out.
  • ordered = true emits in source order through a reorder buffer, so a fixed seed reproduces bitwise at any workers. ordered = false emits batches as they finish, so the epoch's accumulation groups change and runs no longer reproduce bitwise; every batch is still seen exactly once. Applies only to the fan-out; one producer always emits in order.

The transfer runs on one task because device memory cannot be bounded by a semaphore: XLA runs asynchronously and the executable holds its inputs, so there is no point at which the consumer is known to be done. Device buffers are freed explicitly, not left to the GC.

Batching, shuffling and splitting are not provided; use MLUtils.jl.

The wrapper holds only the source and its settings, since build_data runs before batch routing and device placement exist; the training loop builds the pipeline. Base.iterate therefore passes through to the source with no task and no channel, so iterating one by hand cannot leak a producer, and render and predict(nitro, loader) are unaffected by the wrapping. Eval splits stream through eval_stream, which pads a short final batch before the transfer.

ReactantNitro.build_data — Function

ReactantNitro.export_view — Method
export_view(e) -> e_export

The experiment as an exported trace sees it: compile_view(e), which drops every Host field, with every remaining device-resident value copied to the host.

In training, a Device field is a traced input. ReactantNitro.optimizer — Function
optimizer(e) -> Type{<:Optimisers.AbstractRule}

optimizer(e, group::Symbol, hp) -> Optimisers.AbstractRule

The optimizer rule, at one of three levels of control.

Level 0: declare nothing and get RAdam, with per-group hyperparameters from learning_rate and lambda. RAdam rectifies the adaptive variance term, so no hand-tuned warmup is needed; it needs Optimisers 0.4.8, the first release whose Reactant extension traces it.

Level 1: return a rule type, for every group or per group, and the framework constructs it, passing the resolved values by field name. The Decay tail, the per-group accessors and the no-decay mask still apply. A rule with its own lambda field (AdamW) is rejected here, since it would decay twice.

optimizer(::MyExp) = Optimisers.Momentumoptimizer(::MyExp, ::Val{:backbone}) = Optimisers.Momentum

Level 2: build the chain yourself from the group and its resolved, device-converted hp. It is called at setup and again every optimizer step:

optimizer(::MyExp, group::Symbol, hp) = Optimisers.OptimiserChain(    Optimisers.ClipNorm(1.0f0, 2.0f0, false),    Optimisers.Momentum(hp.eta, get(hp, :rho, 0.9f0)),)

hp carries eta (the group's effective learning rate), lambda (already multiplied by it, and nothing when it is zero and not scheduled), anchor, no_decay_mask, and one key per scheduled rule field, present from the first call. A scheduled field reaches the rule only if the factory reads it from hp. Setup checks this on the host: a scheduled field whose value does not change the returned chain is a setup error, and the binding report shows where each scheduled field landed. No level accepts a prebuilt chain with fixed values, since the rules carry device scalars that are rebuilt every step.

ReactantNitro.train! — Method
train!(nitro) -> Nitro
train!(e; kwargs...) -> Nitro

Run the training loop until max_epochs, an early stop or a requested stop, and return the Nitro. The call blocks.

train!(nitro) takes no keywords; every keyword belongs to the Nitro constructor, and train!(e; kwargs...) is sugar for train!(Nitro(e; kwargs...)). The handle is also reachable through run_ref::Ref{Nitro}, filled before the loop starts, and as info.nitro in a phase monitor. To retrain with a different stopping rule, construct another Nitro; the compile cache is module-level, so the new handle reuses every compiled program.

A non-finite loss stops the run with an error naming step and epoch; there is no rollback, and recovery is a resume from the last checkpoint at a lower learning rate. The automatic loop reads the loss back one micro-batch late, so the device runs the next micro-batch while the host waits; the error is therefore raised after at most one more micro-batch (and, at a step's last micro-batch, its optimizer step) has been dispatched, and still names the step the loss belonged to. check_divergence= false turns the stop off: the loss is logged and training continues. Every scalar the framework branches on (the loss, the checkpoint metric, the early-stopping metric) is validated on readback, because a failed BufferToHost on this stack returns garbage without raising; metrics that are only logged are not, nor is the loss under check_divergence = false.

The train line is written every log_every_n_steps optimizer steps and carries the loss, the train_metrics of the step's last micro-batch and, under autolog_schedules, each varying scalar schedule under a schedule/ key. At the end, stop_reason is :completed, :early_stop, :requested or, if the loop threw, :error.

Ctrl+C is a graceful stop: the loop runs on a worker thread, ^C becomes request_stop!, the step loop breaks at its next boundary, validation and the checkpoint still run, and the call returns with stop_reason = :requested.

A handle built with restore_best = true ends every train! that did not fail (completion, early stop, a requested stop) by loading its own run's selected checkpoint into ps and st; step, epoch, history and the last metrics stay as training ended. A further train! on that handle is refused, since those weights beside the final optimizer state and step match no state any run was in; the error lists the constructions that do. With no scored checkpoint it warns and keeps the final weights.

Set the progress reporter and return the previous one. nothing disables progress output; the default is default_progress_reporter. f is called as f(verb::Symbol, label::String, total::Int, epoch::Int, max_epochs::Int), with verb one of:

  • :begin, once per stretch of work, with its label ("train", or the split name), its total units (0 when unknown), and the epoch position.
  • :step, once per completed unit. The other arguments are placeholders.
  • :end, once when the stretch finishes, however it finishes.
  • :done, once when the last stretch of an entry point is over, so a reporter reusing one terminal line can close it. label is the closing text, or "" for the default.
  • :phase, when the current stretch starts or stops doing something that produces no units; label names it ("compiling gradient") or is "" when ordinary work resumes.
  • :note, when the note user code set with progress_note! or with_progress_note changes; label is the note, "" when there is none. A new :phase or :begin clears it.

A reporter that throws is switched off with a warning, and the run continues.

ReactantNitro.MetricHistory

The per-epoch metric series a handle keeps, as returned by history. ReactantNitro.assert_graphconst_hashable — Function
ReactantNitro.assert_graphconst_hashable(e) -> nothing

Refuse at setup a GraphConst value that does not hash and compare by content, since the compile cache and the resume check both rest on hash and isequal meaning "the same configuration". The check: a value and its deepcopy must hash equal and be isequal. A GraphConst{Vector{Int}} passes, since arrays hash by content; a struct containing a mutable field fails, since Base.hash falls through to objectid for it. Such a value would cost a full recompile per handle and a spurious resume refusal with an identical-looking diff, and mutating it in place would reuse a program compiled for the old value. It is refused rather than given a structural hash, which would change every existing key and decide equality for a type whose author has not.
